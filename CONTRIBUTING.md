# Contributing

Thanks for helping. Short version: small pull requests, tests pass, numbers are reproducible.

## Ways to help without writing code
- **Send failed prompts.** A sentence that built the wrong thing, with what you expected, is the most useful report (issue form "Failed prompt"). Real requests teach us more than our own test list.
- **Send results from your machine**: speed, memory, Blender version (issue form "Result report").
- **Show what you built** in Discussions; scenes and prompts that work help other users.
- **Sponsor the training runs**: see "Support the project" in the README.

## Setup
```sh
git clone https://github.com/slm4apps/maris3d && cd maris3d
python3 -m unittest discover -s tests -t .      # no dependencies besides Python 3.9+
python3 scripts/scan_private.py                  # must print "scan: clean"
```
Blender (4.2 or newer; the benchmark was run on 5.2.2) is only needed for `eval/`.

## What we accept
- Plan first: the compiler from words to numbers (`src/maris3d/copilot/compile_plan.py`, `describe_parts.py`), with a test for every new word. A rule may know a word (`on_top_of`, `smooth`), never a thing (`chair`).
- Fixes and tests for the DSL (`src/maris3d/dsl`), checks (`engine/checks.py`), MCP server, bridge, eval runner, docs.
- New benchmark prompts: add them at the **end** of `eval/maris3d_eval/prompts.py` with a reference solution in `tool_refs.py`, never edit or reorder
  existing ones (scores are comparable only on the same list), run `python3 eval/maris3d_eval/validate_tool_refs.py` and `python3 scripts/export_benchmark.py`.
- Result reports from other machines: attach the full result JSON (schema in `eval/result_schema.json`).

## What we do not accept
- Model weights or datasets in the repo (they go to Hugging Face).
- Benchmark claims without the result file and the command that produced it.
- Anything generated by a service whose terms forbid using its output this way (see `docs/LICENSING.md`).

## Style
Python standard library first, no new dependency without a reason. Keep functions small and tested. Commit messages: imperative, one line, optional body.
